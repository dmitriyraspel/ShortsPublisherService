# Task Contract — ShortsPublisherService

**Версия документа:** 1.0  
**Основа:** текущая реализация `Program.cs`, `PublisherOptions.cs` и `ShortsUploadAutomation.cs`.

## 1. Назначение

`ShortsPublisherService` обрабатывает одну задачу за один запуск процесса.

Сервис принимает аргументы командной строки, проверяет видеофайл, при необходимости читает файл метаданных, проверяет Android-устройство, передаёт видео на устройство и возвращает JSON-результат.

Очередь задач, планирование и повторные попытки относятся к внешнему сервису-оркестратору.

## 2. Входной интерфейс

В текущей реализации задача передаётся через аргументы командной строки, а не через единый JSON-объект.

Пример запуска из PowerShell:

```powershell
& ".\bin\Release\net8.0\ShortsPublisher.exe" `
  --task-id "task-123" `
  --file "C:\Videos\ferroli.mp4" `
  --result-file "C:\Results\task-123.json"
```

### Аргументы

| Аргумент | Обязательность | Назначение |
|---|---|---|
| `--file` | Обязателен для обычной обработки | Путь к исходному видеофайлу |
| `--task-id` | Необязателен | Идентификатор задачи |
| `--result-file` | Необязателен | Путь для сохранения JSON-результата |
| `--caption` | Зависит от режима | Текст подписи для режима `--publish-video-youtube` |
| `--help` или `-h` | Необязателен | Вывод справки |

### Правила для пути к видео

- `--file` принимает путь к файлу, а не отдельное имя файла.
- Пример: `--file "C:\Videos\ferroli.mp4"`.
- Сервис преобразует указанный путь в абсолютный с помощью `Path.GetFullPath`.
- Отдельного аргумента `--file-name` нет.
- Имя файла может извлекаться из пути внутри программы, когда оно необходимо для работы с Android-медиатекой.
- Исходный файл на компьютере не удаляется.

### Диагностические аргументы

В `Program.cs` также есть специальные флаги для проверки отдельных шагов UI-автоматизации, в том числе `--diagnose-ui`, `--test-create`, `--test-gallery` и другие.

Они предназначены для разработки и проверки интерфейса, а не являются отдельными типами задач внешнего оркестратора.

**Важно:** `--test-upload-short` нажимает кнопку публикации. Его нельзя запускать без отдельного разрешения на реальную публикацию.

## 3. Метаданные видео

В обычном режиме сервис ищет JSON-файл метаданных рядом с видео.

Например, для:

`C:\Videos\ferroli.mp4`

ожидаемый файл метаданных:

`C:\Videos\ferroli.json`

Сейчас код использует модель `JobMetadata` со следующими свойствами:

| Свойство | Тип | Назначение |
|---|---|---|
| `Title` | `string?` | Заголовок видео |
| `Description` | `string?` | Описание |
| `Visibility` | `string?` | Видимость публикации |
| `MadeForKids` | `bool?` | Признак контента для детей |

Пример JSON метаданных, соответствующий именам свойств текущей C#-модели:

```json
{
  "Title": "Обзор Ferroli",
  "Description": "Описание видео",
  "Visibility": "private",
  "MadeForKids": false
}
```

Если метаданные отсутствуют, текущая реализация использует значения по умолчанию:
- заголовок — имя видеофайла без расширения;
- описание — пустая строка;
- видимость — `Publisher.DefaultVisibility`;
- `MadeForKids` — `Publisher.DefaultMadeForKids`.

Поддерживаемые расширения исходного видео: `.mp4`, `.mov`, `.m4v`. Пустые файлы не допускаются.

## 4. Текущий процесс обработки

1. Разбор аргументов командной строки.
2. Загрузка `appsettings.json` и настроек `Publisher`.
3. Проверка наличия пути к видео.
4. Проверка существования, расширения и размера файла.
5. Чтение метаданных, если соседний JSON-файл существует.
6. Проверка параметров видимости.
7. Вычисление SHA-256 видеофайла.
8. Проверка доступности Android-устройства через ADB.
9. Создание каталога для видео на устройстве.
10. Копирование видео на Android.
11. Запуск сканирования медиатеки.
12. Вызов автоматизации публикации с учётом настройки `DryRun`.
13. Формирование JSON-результата и возврат кода завершения процесса.

Фактическая публикация в текущей версии не реализована полностью и не должна считаться успешной только потому, что видео было скопировано на устройство.

## 5. Контракт результата

JSON-результат выводится в стандартный поток вывода. Если указан `--result-file`, тот же результат дополнительно записывается в файл.

Текущая модель результата — `JobResult`:

| Поле | Тип | Назначение |
|---|---|---|
| `TaskId` | `string?` | Идентификатор задачи |
| `Status` | `string` | Статус выполнения |
| `Success` | `bool` | Успешность обработки в соответствии с текущей логикой |
| `Published` | `bool` | Признак публикации по текущей логике |
| `File` | `string?` | Абсолютный путь к исходному файлу |
| `Message` | `string` | Описание результата |
| `Sha256` | `string?` | Хеш видео |
| `StartedAtUtc` | `DateTimeOffset` | Время начала |
| `CompletedAtUtc` | `DateTimeOffset` | Время завершения |

Имена полей в JSON сейчас соответствуют именам свойств C# (`PascalCase`), поскольку сериализация не задаёт политику преобразования имён.

### Пример результата Dry Run

```json
{
  "TaskId": "task-123",
  "Status": "dry_run_completed",
  "Success": true,
  "Published": false,
  "File": "C:\\Videos\\ferroli.mp4",
  "Message": "Validation and ADB transfer succeeded. Dry run only: YouTube publication was not attempted.",
  "Sha256": "пример-хеша",
  "StartedAtUtc": "2026-10-21T07:00:00+00:00",
  "CompletedAtUtc": "2026-10-21T07:00:05+00:00"
}
```

Это пример структуры результата, а не утверждение, что конкретный запуск уже состоялся.

## 6. Статусы и коды завершения

### Статусы

| Статус | Значение |
|---|---|
| `dry_run_completed` | Проверки и передача видео выполнены без попытки публикации |
| `failed` | Обработка завершилась ошибкой |
| `invalid_arguments` | Переданы неизвестные аргументы либо отсутствует обязательный путь |

В текущем коде предусмотрен также статус `published` для ветки, где `DryRun` отключён и метод автоматизации вернулся без ошибки. Однако текущая реализация `PublishShortAsync` в живом режиме выбрасывает `LIVE_UPLOAD_NOT_IMPLEMENTED`, поэтому фактическую успешную публикацию этот код пока не обеспечивает.

### Коды завершения процесса

| Код | Значение |
|---|---|
| `0` | Выполнение завершилось согласно текущей логике; сам по себе код не означает публикацию |
| `1` | Ошибка обработки |
| `2` | Ошибка аргументов командной строки |

Внешний оркестратор должен учитывать и код завершения, и содержимое JSON-результата.

## 7. Текущие ограничения

1. Единого JSON-входа для всей задачи пока нет.
2. `--task-id` необязателен в текущем CLI.
3. `--caption` не является универсальным полем обычного режима обработки.
4. Поле `platform` пока не входит в интерфейс обычной обработки.
5. Текущий `JobResult` не содержит этап выполнения (`stage`) и структурированный объект ошибки.
6. Неизвестный результат публикации не представлен отдельным статусом `unknown`.
7. Текущая логика не подтверждает публикацию на YouTube end-to-end.

Эти пункты фиксируют состояние реализации и не означают, что ограничения обязательно должны остаться в следующей версии.

## 8. Безопасность и диагностика

- Настройка `DryRun` по умолчанию должна оставаться включённой до завершения проверки автоматизации.
- Нельзя сообщать об успешной публикации без подтверждения результата на платформе.
- Исходный видеофайл на компьютере сохраняется.
- XML и другие диагностические артефакты сохраняются на этапе разработки.
- Технический лог должен вестись отдельно от JSON-результата задачи.
- Отключение диагностических артефактов в обычном режиме выполняется после завершения и проверки автоматизации.
- Сервис не должен самостоятельно повторять задачи: повторные попытки относятся к оркестратору.

## 9. Направление дальнейшего развития

После согласования текущего контракта можно отдельно спроектировать и реализовать унифицированный интерфейс задачи, который будет поддерживать платформу, путь к видео, метаданные и структурированный результат.

Такое изменение должно быть выполнено согласованно в `Program.cs`, модели результата, обработке ошибок, документации и тестах. До этого момента фактическим интерфейсом остаются аргументы командной строки и соседний JSON-файл метаданных.
